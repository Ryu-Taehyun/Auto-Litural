# Auto-Litural

**사용해서 로그. LLM에 탐지되도 전 책임 안집니다...**

[ALEPH](https://aleph-omega.vercel.app)의 아침·마무리 리추얼 입력을 CSV 문장으로 채우는 Windows용 Python Playwright 자동화입니다. 기존 콘솔 실행과 로컬 웹 UI를 함께 제공합니다.

> 이 프로그램 사용으로 평가 점수 하락 등 불이익이 발생하더라도 개발자는 책임을 지지 않습니다. 사용 여부와 입력 내용 확인에 대한 책임은 사용자에게 있습니다.

자동 입력만으로 최종 저장하지 않습니다. 일반 모드와 기존 CLI는 Chrome에서 직접 저장하고, 헤드리스 모드는 웹 UI에서 결과를 검토한 뒤 저장을 요청합니다.

## 준비물

- Windows, Python 3, Google Chrome
- 기본 Chrome 경로: `C:\Program Files\Google\Chrome\Application\chrome.exe`
- 처음 실행할 때 패키지를 설치할 수 있는 인터넷 연결

## 웹 UI 실행

1. 저장소를 내려받아 압축을 풀고 **`web.cmd`**를 더블클릭합니다.
2. 자동으로 열리지 않으면 **http://127.0.0.1:8765**에 접속합니다.
3. **로그인 열기**를 누르고 웹 UI 전용 Chrome에서 Google 로그인을 직접 완료합니다. 이미 로그인한 학습 화면이 있으면 그 탭을 그대로 사용합니다. 튜토리얼 화면이라면 먼저 마치고 학습 메뉴가 보이는지 확인하세요.
4. 아침·마무리를 선택하고 동료 이름 1~3명을 입력합니다. 쉼표 또는 띄어쓰기로 구분합니다.
5. 필요하면 **헤드리스 실행**을 켜고 **입력·클릭 사이 딜레이**를 지정합니다. Instant는 추가 대기 없이, Humanize는 동작마다 6~12초 무작위 대기로 실행합니다. 직접 설정은 기본 300ms이며 0~3000ms 범위입니다.
6. **리추얼 실행하기**를 누르고 화면 안의 경고 창에서 **확인하고 실행**을 선택합니다. 취소 또는 Esc를 누르면 실행하지 않습니다.
7. 일반 모드는 Chrome에서 내용을 확인하고 직접 저장합니다. 헤드리스는 아래 결과 이미지를 검토하고 **확인한 내용 저장하기**를 누른 뒤 저장 확인 창에서 확인합니다.

실행 중에는 콘솔 창을 열어 두세요. **실행 중지**는 자동화를 취소하며 이미 입력된 내용은 되돌리지 않습니다. 서버 종료는 콘솔에서 **Ctrl+C**입니다. UI 탭만 닫아서는 서버나 작업이 종료되지 않습니다.

마무리 리추얼을 실행하려면 사이트에서 **오늘 아침 리추얼을 먼저 저장**해야 합니다. 오늘 기록이 있으면 기존 자동화가 수정 화면에 들어가 입력을 채웁니다. 실행 전 계정과 입력 내용을 확인하세요.

## 로그인과 실행 옵션

웹 UI는 `%LOCALAPPDATA%\AutoLituralWebChrome` 전용 프로필과 로컬 디버깅 포트 9223을 사용합니다. 처음 한 번은 이 프로필에서 직접 로그인해야 합니다. 기존 CLI의 ChromeDebug 프로필과 포트 9222는 그대로 보존합니다.

일반 실행은 로그인한 학습 화면 탭을 우선 재사용하며 로그인 페이지를 다시 열지 않습니다. 관련 탭이 전혀 없을 때만 새 탭을 만듭니다.

헤드리스는 로그인한 탭의 쿠키·localStorage·sessionStorage·IndexedDB를 메모리로 복사해 새 창 없이 입력합니다. 로그인 페이지를 거치지 않고 기존 학습 화면 경로에서 시작합니다. Chrome이 열려 있으면 해당 탭의 상태를 복사하고, 닫혀 있으면 저장된 전용 프로필을 헤드리스로 직접 엽니다. 프로필이 다른 Chrome에 잠겨 있으면 안내 오류로 종료합니다. 헤드리스 입력 완료 후 결과 확인을 기다리는 동안에도 새 작업은 시작하지 않습니다. 저장 요청·중지·오류 시 작업용 헤드리스 브라우저가 닫히며, 저장하지 않은 입력은 사라집니다.

딜레이는 리추얼의 각 입력·클릭·체크 직전에 적용합니다. Google 로그인에는 적용하지 않습니다. 일반 로그인 대기는 약 5분이며, 전체 작업 제한은 결과 검토 대기를 포함해 15분입니다.

서버는 이 컴퓨터의 `127.0.0.1`에만 연결합니다. 제어 토큰·Host·동일 출처 검사를 적용하고 임의 명령이나 파일 경로를 받지 않습니다. 인터넷 공개용 서버가 아니므로 공개 터널이나 포트 포워딩으로 노출하지 마세요. 로그와 결과 이미지는 메모리에 유지하며 새 작업 또는 서버 재시작 시 초기화됩니다.

자세한 구조와 문제 해결은 [WEB_UI.md](WEB_UI.md)를 참고하세요.

## 기존 콘솔 실행

| 파일 | 하는 일 |
|---|---|
| `morning.cmd` | 아침 리추얼 (`main.py`) |
| `close.cmd` | 마무리 리추얼 (`close.py`) |
| `web.cmd` | 로컬 웹 UI |

처음 실행하면 `.venv` 생성과 `requirements.txt` 패키지 설치를 진행합니다. 기존 Python·CMD·CSV 기반 CLI 흐름은 유지됩니다.

아침은 호흡 → 편안했던 장면 → 강점·가치 → 동료 인정 → 긍정 목표 순서로 입력합니다. 마무리는 강점 행동 돌아보기 → 감사 나누기 → 감사일기 순서입니다. 동료 수에 맞춰 입력 행을 조절합니다. 기존 호흡 단계는 시작 직후 종료하므로 시간이 거의 0분으로 기록됩니다.

```text
web_ui/worker.py          기존 Python 자동화 연결·로그인·딜레이·중지
web_ui/ui_chrome.py       웹 UI 전용 Chrome 프로필·포트 9223
web_ui/index.html         한국어 대시보드·화면 안의 경고 창
web_ui/app.js             실행·진행상황·로그·결과 이미지·저장 요청
web_ui/style.css          반응형 화면 스타일

```

## CSV 문장

GitHub에 반영된 최신 문장 수정본을 유지합니다.

| 파일 | 행 수 | 쓰이는 곳 |
|---|---:|---|
| `Title.csv` | 1,000 | 아침 |
| `1.csv` ~ `7.csv` | 각 500 | 아침 |
| `close_*.csv` 5개 | 각 900 | 마무리 |

문장 항목은 총 9,000개이며 `2.csv`·`3.csv`·`5.csv`의 `문장` 머리글은 제거되어 있습니다. `Name.csv`는 기존 이름 3개를 유지하며 현재 실행에서는 사용하지 않습니다. 이름은 실행할 때 입력합니다.

문장을 바꿀 때는 한 줄에 하나씩 작성합니다. 쉼표를 넣으면 첫 열까지만 읽혀 문장이 잘릴 수 있습니다. 팀플·조별·모둠·조모임·공동 작업·발표처럼 아직 겪지 않았을 수 있는 상황은 문장에 넣지 않습니다.

## 문제 해결

| 증상 | 확인할 사항 |
|---|---|
| `'t'`, `'ho'`, `'p'`를 명령으로 인식 | `web.cmd`의 CRLF 줄바꿈을 보존해야 합니다. 저장소의 파일을 그대로 사용하세요. |
| 서버가 열리지 않음 | 콘솔 오류를 확인하고 http://127.0.0.1:8765 에 접속하세요. 포트 충돌 시 `web.cmd --port 8766`을 사용할 수 있습니다. |
| Chrome 시작 실패 | `chrome.py`의 설치 경로와 웹 UI용 9223 포트를 확인하세요. |
| Google 로그인으로 이동하지 않음 | 로그인용 전용 Chrome에서 직접 버튼을 눌러 보고 로그의 로딩·인증 오류를 확인하세요. 오래된 ChromeDebug 인증 상태와 분리하기 위해 웹 UI는 별도 프로필을 사용합니다. |
| 로그인 후 계속 대기 | 웹 UI는 `/tutorial`, `/cortex` 및 각각의 `.html` 주소를 인식합니다. 다른 주소라면 학생 화면 경로와 사이트 변경 여부를 확인하세요. |
| 자동 입력 오류 | 현재 Chrome 화면, 오늘 아침 저장 여부, `main.py`·`close.py`의 사이트 선택자를 확인하세요. |
| 헤드리스 저장 요청 완료 | 이 표시는 저장 버튼 클릭을 뜻합니다. 결과 이미지에서 사이트의 저장 성공 여부를 확인하세요. |

## 검증

```powershell
python -m unittest discover -s tests -p test_web_ui.py -v
```

23개 테스트에서 접근 보호, 옵션 검증, 작업 관리·중지, 결과 이미지 접근, 명시적 저장 명령 전달, 원본 아침·마무리 함수 연결과 자동 최종 저장 미호출을 확인했습니다. 원본 입력 흐름은 가짜 페이지로 검사합니다. 로컬 HTML과 실제 헤드리스 Chrome에서는 딜레이·미리보기·저장 전 대기·저장 버튼 클릭·딜레이 도중 취소를 확인했습니다. 별도 세션 회귀 검증에서는 새 탭·이동 없이 기존 탭을 재사용하고 네 종류의 저장소를 별도 헤드리스 Chrome에 복원한 뒤 학습 메뉴가 표시되는 것을 확인했습니다. 이 검증의 네트워크 요청은 모두 로컬 테스트 화면으로 대체했습니다.

실제 사용자가 새 전용 프로필에서 Google 로그인을 완료한 뒤 `/tutorial`로 돌아와 프로그램이 `로그인 확인 완료`를 인식하는 것까지 확인했습니다. 현재 외부 사이트에서 리추얼 입력·저장 전체 흐름은 검증하지 않았습니다.

헤드리스의 IndexedDB 복사를 위해 Playwright 1.51 이상이 필요하며 requirements.txt에 명시합니다. [Playwright storage_state 문서](https://playwright.dev/python/docs/api/class-browsercontext#browser-context-storage-state)를 참고하세요.

튜토리얼에서 학습 메뉴가 보이지 않을 때는 입력 전에 안내하고 종료합니다. 튜토리얼을 마쳐 학습 메뉴가 보이는 화면에서 실행하세요. 실제 저장된 사용자 프로필로 Chrome 창 없이 학습 메뉴까지 열리는 것을 확인했습니다. 리추얼 입력·저장 전체 흐름은 이번 수정에서 실행하지 않았습니다.

## 로그인 후 멈춤과 기존 Chrome 재연결

Windows에서 중지 신호를 기다리는 입력 스레드를 먼저 시작한 뒤 NumPy/pandas를 가져오면 네이티브 모듈 로딩이 멈출 수 있어, 자동화 모듈을 먼저 준비한 뒤 중지 대기를 시작합니다. 준비 단계는 웹 UI 로그에 표시됩니다.

기존 Chrome에 새로 연결하면 Playwright 저장소 내보내기에 이미 열린 탭의 origin이 빠질 수 있습니다. 헤드리스 복사 시 필요한 경우 같은 컨텍스트의 임시 백그라운드 탭에 로컬 빈 문서를 제공해 origin을 등록하고 localStorage·IndexedDB를 함께 내보냅니다. 원래 로그인 탭은 이동하지 않으며 임시 탭은 자동으로 닫습니다. 추가 Chrome 창이나 로그인 화면을 열지 않습니다.

이 회귀 상황은 `python tests/check_cdp_session.py`로 검증할 수 있습니다. 테스트용 Chrome과 임시 프로필을 사용하고 사이트 요청은 로컬 응답으로 대체합니다. 실제 로그인 세션에서도 헤드리스로 아침 리추얼 화면까지 이동하는 것을 확인했습니다. 이 확인에서는 기록 수정·입력·저장을 수행하지 않았습니다.


## 테마와 입력 속도

오른쪽 위 테마 버튼으로 다크/라이트를 전환합니다. 첫 방문에는 운영체제 테마를 따르고 이후 선택은 브라우저에 저장합니다. 입력 속도 선택도 새로고침 후 유지됩니다.

- **Humanize**: 각 입력·클릭·체크 전에 6~12초 범위에서 매번 새 대기 시간을 뽑습니다. 대기 시간은 로그에 표시하며 중지 요청으로 취소할 수 있습니다. Google 로그인에는 적용하지 않습니다.
- **Instant**: 임의의 추가 딜레이 없이 진행합니다. 사이트 로딩·입력 가능 여부 확인과 필요한 화면 전환은 기다립니다.
- **직접 설정**: 기존 0~3000ms 딜레이 기능입니다. 웹 UI의 첫 선택은 Instant이며, 기존 API 요청에서 속도 옵션을 생략하면 종전의 고정 딜레이를 사용합니다.

새 속도 옵션은 서버 재시작이 필요합니다. 기존 실행 콘솔을 Ctrl+C로 종료하고 web.cmd를 다시 실행한 뒤 화면을 새로 고치세요. 구버전 서버가 실행 중이면 속도를 적용하지 않은 채 실행되는 것을 막고 재시작 안내를 표시합니다.

검증에서 Humanize가 매 동작마다 별도 무작위 값을 선택하는 것, Instant가 추가 대기를 생략하는 것, 대기 중 취소와 API 옵션 검증을 확인했습니다. 화면에서는 다크/라이트 전환·선택 유지·속도별 안내·실행 경고 표시를 실제 자동화가 차단된 미리보기로 확인했습니다. Humanize는 문장 자체를 다시 쓰는 기능이 아니라 입력 타이밍을 조절하는 옵션입니다.


## Auto-Litural-Terminal

별도 터미널 버전은 [Auto-Litural-Terminal](Auto-Litural-Terminal/README.md) 폴더에 있습니다. 해당 폴더의 start.cmd를 실행하세요. 보라색 shadow 배너, 1~5번 메뉴, 설정 검증·실행 전 경고, Humanize/Instant/Custom 속도와 Ctrl+C 중지를 제공합니다. 설정 작업 후 화면을 정리하며 실행 결과는 Enter로 확인한 뒤 메뉴로 돌아갑니다. 최종 저장은 Chrome에서 직접 수행합니다.

터미널 검사 15개가 통과했으며 실제 사이트 입력·저장은 이 추가 작업에서 검증하지 않았습니다.
